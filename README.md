# Train321 Marketing Site

Standalone marketing site for **train321.com**. Built with **Nuxt 3** + **Sanity** (headless CMS), deployed as static HTML to **Vercel** for SEO.

The LMS app lives in a separate repo (`train321-merged`) and is reached via Sign In / Enroll buttons that link to `app.train321.com`.

---

## Quick start

```bash
# 1. Install
npm install
cd studio && npm install && cd ..

# 2. Configure Sanity (one time)
#    a. Create a free project at https://sanity.io/manage
#    b. Copy the project ID
cp .env.example .env
# Edit .env, set SANITY_PROJECT_ID
cp studio/.env.example studio/.env
# Edit studio/.env, set SANITY_STUDIO_PROJECT_ID

# 3. Run the marketing site
npm run dev
# → http://localhost:3000

# 4. Run the Sanity Studio (separate terminal)
npm run studio:dev
# → http://localhost:3333
```

## What's set up

### Marketing site (Nuxt 3)
- **All 13 pages** copied from the old monorepo and converted to Nuxt 3 conventions (`<router-link>` → `<NuxtLink>`, lifecycle hooks updated, import paths updated).
- **Header / Footer** rewritten for Nuxt with the embedded sign-in modal replaced by a link to `${APP_BASE}/login` — auth lives in the LMS app, not here.
- **Routes:**
  - `/` → Home
  - `/individuals` → Home variant for individual learners
  - `/catalog` → **Sanity-driven** course catalog (the reference page — see below)
  - `/about`, `/contact`, `/faq`, `/services`, `/testimonials`, `/demo`
  - `/blog` and `/blog/[slug]`
  - `/courses/[slug]` (was `/[slug]` — see "URL change" below)
  - `/legal/[slug]` (was `/[slug]` — see "URL change" below)
- **Sitemap** auto-generated by `@nuxtjs/sitemap` at `/sitemap.xml`.
- **SEO** wired via `useSeoMeta()` per page; `app.head` in `nuxt.config.ts` sets defaults.

### Sanity Studio (`/studio`)
- **Schemas defined:** `siteSettings` (singleton), `homePage` (singleton), `course`, `blogPost`, `testimonial`, `faqItem`, `service`, `legalPage`, `teamMember`, plus reusable `seo` and `callToAction` objects.
- **Custom desk structure** in `studio/sanity.config.ts` groups singletons at the top.

### Catalog wired to Sanity (the reference)
[pages/catalog.vue](pages/catalog.vue) is the working example of:
- `useSanityQuery()` with GROQ at build time (SSG-friendly)
- `urlFor()` to build CDN image URLs
- Linking out to the LMS for enrollment via `runtimeConfig.public.appBase`

The other 12 pages still use the static data files in `assets/data/` — they work as-is. **Migrate them one at a time** following the Catalog pattern.

## How content editing works

1. Editors go to `studio.train321.com` (once deployed) or `localhost:3333` (in dev).
2. Sign in with Google / email/password.
3. Pick a section (Courses, Blog, Testimonials, FAQ…).
4. Edit fields — text, images, rich text, references.
5. Hit **Publish**.
6. The marketing site rebuilds (~30 sec on Vercel) and the change is live.

## Calling your LMS API (pricing, live data)

The marketing site can fetch from your existing API at `${apiBase}` (default `https://api.train321.com`). Three patterns:

```vue
<script setup>
const config = useRuntimeConfig();

// 1. Build-time (SSG): pricing baked into HTML. Fast, SEO-perfect.
//    Trigger Vercel rebuild on price change via webhook.
const { data: pricing } = await useFetch(`${config.public.apiBase}/courses/food-handler/pricing`);

// 2. Server-side render: fetched fresh on each request.
//    Use for content that changes constantly.
const { data: liveSeats } = await useFetch(`${config.public.apiBase}/seats/available`);

// 3. Client-side only: fetched in browser, after page loads.
//    Use for per-user data — won't affect SEO either way.
const { data: cart } = await useFetch(`${config.public.apiBase}/cart`, { server: false });
</script>
```

See [composables/useCourses.ts](composables/useCourses.ts) for an example of mixing Sanity (display price) with a live API call.

## Deploying

### Marketing site (Vercel — recommended)
1. Push this repo to GitHub.
2. Go to vercel.com, import the repo.
3. **Framework preset:** Nuxt
4. **Build command:** `npm run generate` (for SSG) or `npm run build` (for SSR)
5. **Environment variables:**
   - `SANITY_PROJECT_ID`
   - `SANITY_DATASET` (usually `production`)
   - `APP_BASE` (e.g. `https://app.train321.com`)
   - `API_BASE` (e.g. `https://api.train321.com`)
   - `SITE_URL` (e.g. `https://train321.com`)
6. Add custom domain `train321.com` in Vercel → Settings → Domains.

### Studio (Sanity-hosted, free)
```bash
cd studio
npm run deploy
# Pick a hostname → studio.train321.com requires DNS CNAME setup separately.
# Default hostname: <your-project>.sanity.studio
```

To use `studio.train321.com`:
1. In your DNS provider, add CNAME `studio` → `studio.sanity.build`.
2. In `studio/sanity.config.ts`, deploy with `sanity deploy --custom-domain studio.train321.com`.

## URL changes from the old site

The original SPA routed course/legal pages at the root level (`/food-handler`, `/privacy-policy`). The new site groups them:

| Old | New |
|---|---|
| `/food-handler` | `/courses/food-handler` |
| `/privacy-policy` | `/legal/privacy-policy` |

**Why:** cleaner URL hierarchy, no risk of slug collisions (e.g. if you ever add a "company" page named the same as a course family).

**To preserve SEO**, add 301 redirects in `nuxt.config.ts`:
```ts
routeRules: {
  '/food-handler': { redirect: { to: '/courses/food-handler', statusCode: 301 } },
  '/privacy-policy': { redirect: { to: '/legal/privacy-policy', statusCode: 301 } }
  // ...etc per old slug
}
```

## Migrating remaining pages to Sanity

Pattern from [pages/catalog.vue](pages/catalog.vue):

1. Define / verify the schema in `studio/schemas/` (most are already done).
2. In the page's `<script setup>`, replace the static import with `useSanityQuery()`:
   ```ts
   // Before:
   import { faqs } from "~/assets/data/faqs";

   // After:
   const { data: faqs } = await useSanityQuery(groq`
     *[_type == "faqItem"] | order(category asc, order asc)
   `);
   ```
3. Adjust template field references where Sanity field names differ.
4. Populate the content in Studio.
5. Verify and remove the now-unused `assets/data/<file>.js`.

Suggested order (easiest → hardest):
1. **FAQ** (`pages/faq.vue`) — simple list, smallest schema
2. **Testimonials** — already has a schema, simple
3. **Services** — simple
4. **Blog** + Blog Article — straightforward, just rich text
5. **Legal pages** — simple rich text
6. **About** + Team — multi-section
7. **Contact** — mostly static, low priority
8. **Demo** — mostly static
9. **Course detail pages** (`pages/courses/[slug].vue`) — biggest, most fields
10. **Home** — biggest, many sections; do last when patterns are settled
